# Sundermeyer Reunion Fe–Mg comparisons

Run `python examples/validation/check_reunion.py` from the repository root. The script reads the two normalized profile CSVs already in `examples/validation/profiles/`, embeds the selected profile windows and source setup, and writes `reunion_results.json`. It does not read or require the original Excel workbook. The output records the actual fitted and published-time RMSE values, conditions, diffusivities, and coefficient warnings.

The source is Sundermeyer et al. (2020), *Contributions to Mineralogy and Petrology* 175, DOI [10.1007/s00410-019-1642-y](https://doi.org/10.1007/s00410-019-1642-y). The article's methods (pp. 5–8) say that they fit a one-dimensional, composition-dependent Mg–Fe profile with an initially unzoned crystal and a fixed melt-equilibrium rim boundary. The far interior is treated as unmodified. It specifies 1 kbar, average fO₂ NNO−0.5, MI temperatures, ±0.2 mol% Fo, the anisotropy relation 6Da = 6Db = Dc, and Chakraborty (2010) for the c-axis coefficient. Online Resource 3, sheet `REU 150915-1`, provides the sample-specific initial and boundary Fo, crystal/profile angles, grid spacing, published duration, and uncertainty. Online Resource 2, sheet `Melt inclusions`, provides MI temperatures. Online Resource 1, sheet `REU 150915-1`, supplies measured traverses.

The app's source-era coefficient is `ol_FeMg_dohmen_chakraborty2007_tamed`. Chakraborty (2010, p. 617) prints the same expression for fO₂ above 10⁻¹⁰ Pa (10^−9.21 (fO₂/10⁻⁷)^1/6 10^3(X_Fe−0.1) exp(−(201000 + (P−10⁵)·7×10⁻⁶)/RT), D_a ≈ D_b ≈ D_c/6; checked on the rendered page on 8 October 2026), and the Réunion fO₂ near 2×10⁻⁴ Pa is in that branch, so this is the law the paper cites. The alternative `ol_FeMg_oeser2026` provides a newer tracer-derived law. Its reported calibration is San Carlos Fo91.5, high-silica fO₂ near 10⁻⁵ Pa, atmospheric pressure, and 1100–1250 °C. Reunion inputs (Fo about 80–85, fO₂ near 2×10⁻⁴ Pa, and 0.1 GPa) sit outside those composition, fO₂, and pressure calibration ranges. Treat alternative times as an extrapolation sensitivity, not a replacement estimate.

All distances and Fo values above come from the normalized profile CSVs. The selected windows implement the paper's Fig. 3 description: the diffusion section begins at the first point more than 0.2 Fo from the assigned core plateau, and the late outermost rim is omitted. The article does not publish row indices for the fits; these are therefore explicit reconstructions. Online Resource 3's author-selected `dx_um` is recorded in the JSON but is not used to resample the sparse measured data. Both masks use fixed source-distance bounds, so the exact points selected are reproducible offline.

For 150915-1-9, extending the closed far-field from 20 to 120 µm beyond the fitted window, while keeping approximately the same numerical spacing, changes the source-law best-fit time from 358.12 to 357.10 d (−0.28%). The artificial far boundary is therefore not controlling this case at that resolution. This is a numerical-domain check, not evidence that all aspects of the source geometry are reproduced.

The 1-3 result should not be presented as a reproduction: its time is 5.65 times the paper's best fit. The 1-9 fit is 0.62 times the paper's best fit and below the stated interval. Potential contributors include the source's exact point selection/resampling and use of DIPRA, as well as the coefficient implementation. The source notes that one-dimensional fits may overestimate times if diffusion occurred in multiple directions, but that caveat does not explain away the specific mismatch.

For a future GUI preset, expose the measured CSV and mask, core Fo, rim Fo, MI temperature and its provenance, pressure, fO₂ buffer offset, three profile-to-crystal-axis angles, and coefficient choice. For these examples the defaults can be 1 kbar, NNO−0.5, fixed rim Dirichlet, closed far interior, and ±0.2 mol% Fo. The preset should label the 1-3 temperature as proxy and both masks as reconstructed. A source-era reproduction preset should name the TaMED entry as the Chakraborty (2010) expression the paper cites. The 1-9 inputs make a useful onboarding/demo case; neither result should be advertised as matching the published answer yet.
